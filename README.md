# 최신 글 자동 감지 → 음성 다운로드 → 텍스트 변환 → 텔레그램 전송 봇

daininvest.co.kr 같은 로그인 필요 사이트에서 **게시판의 가장 최신 글**을 자동으로 확인해서,
이전과 다르면 들어가 음성을 다운로드하고 텍스트로 변환한 뒤, 결과를 텔레그램으로
받아보는 완전 무료 자동화 봇입니다.

## 전체 구조
- **실행 장소**: GitHub Actions (public 저장소면 완전 무료, private면 월 2,000분 무료) — 기본 30분마다 자동 실행
- **로그인/다운로드**: Playwright (헤드리스 브라우저)
- **새 글 감지**: 매 실행마다 게시판 맨 위(최신 글)를 확인해서, 마지막으로 처리한 글
  (`last_seen.json`에 저장)과 다르면 새 글로 판단
- **텍스트 변환**: faster-whisper (오픈소스 로컬 모델, API 비용 없음)
- **알림**: 텔레그램 봇 API (글 제목 + 변환된 텍스트 전송)

> ⚠️ 한 번 실행하는 사이에 글이 2개 이상 새로 올라오면, 가장 최신 글 1개만 처리하고
> 중간 글은 건너뜁니다. 실행 주기(기본 30분)를 짧게 할수록 놓칠 확률이 줄어들어요.

## 1. 텔레그램 봇 만들기
1. 텔레그램에서 `@BotFather` 검색 → 대화 시작
2. `/newbot` 입력 → 이름 설정 → **봇 토큰(TELEGRAM_BOT_TOKEN)** 받기
3. 만든 봇과 아무 대화나 한 번 나누기 (메시지 아무거나 전송)
4. 브라우저에서 아래 주소 접속해서 **chat_id** 확인
   `https://api.telegram.org/bot<봇토큰>/getUpdates`
   응답 JSON에서 `"chat":{"id": 123456789}` 부분의 숫자가 **TELEGRAM_CHAT_ID**

## 2. GitHub 저장소 만들기
1. github.com에서 새 저장소 생성 (public 추천 - 완전 무료)
2. 이 폴더(`main.py`, `requirements.txt`, `.github/workflows/run.yml`, 이 README)를
   그대로 저장소에 업로드/커밋

## 3. 비밀값 등록 (Secrets) — 절대 코드에 직접 적지 마세요
저장소 → Settings → Secrets and variables → Actions → New repository secret
아래 4개를 각각 등록:
- `SITE_ID` : 사이트 로그인 아이디
- `SITE_PW` : 사이트 로그인 비밀번호
- `TELEGRAM_BOT_TOKEN` : 1번에서 받은 봇 토큰
- `TELEGRAM_CHAT_ID` : 1번에서 확인한 chat id

## 4. 사이트에 맞게 코드 수정 (중요!)
`main.py` 상단의 ⚠️ 표시된 selector 6곳을 실제 사이트 구조에 맞게 바꿔야 합니다.
요소를 우클릭 → "검사(Inspect)" → 강조된 HTML에서 다시 우클릭 → "Copy" → "Copy selector"
로 뽑아서 아래 변수에 붙여넣으면 됩니다.

- `ID_INPUT_SELECTOR` (로그인 아이디 입력창)
- `PW_INPUT_SELECTOR` (로그인 비밀번호 입력창)
- `LOGIN_BUTTON_SELECTOR` (로그인 버튼)
- `LIST_URL` (음성 글들이 올라오는 게시판 목록 페이지 URL)
- `POST_LINK_SELECTOR` (목록에서 글 제목 링크의 selector — 맨 위 글이 최신 글이어야 함)
- `PLAY_BUTTON_SELECTOR` (글 안에서 음성 재생 버튼)

`POST_LINK_SELECTOR`를 찾는 팁: 게시판 목록에서 글 제목 하나를 우클릭 → 검사 →
강조된 `<a>` 태그의 class를 확인하면, 보통 다른 글 제목들도 똑같은 class를 가지고
있어서 한 번에 전부 선택할 수 있어요. (코드는 그중 맨 첫 번째, 즉 최신 글만 사용합니다)

⚠️ 만약 게시판이 "오래된 글이 맨 위"로 정렬되어 있다면, `main.py`의
`get_latest_post()` 함수에서 `links[0]`을 `links[-1]`로 바꿔주세요.

## 5. 새 글 감지 방식 (심플 버전)
- 매 실행마다 게시판 **맨 위 글 하나만** 확인합니다.
- 그 글의 URL을 `last_seen.json`에 저장된 URL과 비교해서, 다르면 "새 글"로 판단합니다.
- 처리에 성공하면 `last_seen.json`을 갱신하고, 워크플로우가 자동으로 저장소에
  다시 커밋합니다 (그래야 다음 실행 때도 기억함).
- 처리 중간에 오류가 나면 `last_seen.json`을 갱신하지 않아, 다음 실행 때 같은 글을
  다시 시도합니다.
- 한 번 실행 사이에 글이 2개 이상 올라오면 **가장 최신 글 1개만** 처리되고 중간
  글은 건너뜁니다. 자주 확인할수록(예: 10분마다) 놓칠 확률이 줄어요.

## 6. 실행
- 글이 보통 **8:30 / 9:30 / 11:30 / 14:30 (±30분)**에 올라온다고 해서, 기본값은
  두 블록으로 나눠서 체크해요 (`.github/workflows/run.yml`):
  - **아침 블록**: KST 08:00, 08:30 — `cron: "0,30 23 * * 0-4"`
  - **오전~오후 블록**: KST 09:00~12:30, 14:00~15:30 (30분 간격) — `cron: "0,30 0-3,5,6 * * 1-5"`
  - 그 사이(12:30~14:00 KST)는 글이 안 올라오는 시간이라 체크를 쉽니다.
  - 주말에도 올라오면 `0-4`를 `0-6`으로, `1-5`를 `*`로 각각 바꾸세요.
  - ⚠️ cron은 **UTC 기준**이에요. 한국 아침 8시대는 UTC로 "전날 23시대"가 되어
    날짜가 하루 당겨지기 때문에, 아침 블록만 요일을 하루 앞당겨(일~목) 적용했어요.
    시간대를 직접 조정하실 땐 이 부분을 꼭 신경 쓰세요.
- 바로 테스트하고 싶으면: 저장소 → Actions 탭 → "audio-to-text-bot" →
  "Run workflow" 버튼으로 수동 실행 가능
- 첫 실행 시 `last_seen.json`이 비어있으므로, 그 시점의 최신 글 1개가 바로
  처리되어 텔레그램으로 전송됩니다.

## 주의사항
- 이 자동화는 본인 계정으로만 사용하세요. 사이트 이용약관에 자동 접속(스크래핑)을
  금지하는 조항이 있는지 꼭 확인하시는 게 안전해요.
- 음성이 HLS/DASH 스트리밍(.m3u8, .ts 조각)으로 되어 있으면 이 코드로는 바로 안 되고
  추가 처리가 필요할 수 있어요. 그런 경우 캡처된 URL 패턴을 알려주시면 코드를 더
  보완해드릴 수 있어요.
- `faster-whisper`의 "small" 모델은 속도/정확도 균형이 괜찮은 편이지만, 더 정확하게
  하고 싶으면 `main.py`에서 `"small"`을 `"medium"`으로 바꾸세요 (대신 느려짐).
